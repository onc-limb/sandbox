### 学んだ概念

**所有権と借用の基本モデル**

- メソッドが値をどう扱うかはシグネチャの self の形で決まる:
  `&self`＝共有借用（`len`, `contains`）/ `&mut self`＝排他借用（`push_str`, `entry`）/
  `self`＝所有権ごと消費（`into_bytes`, `count`, `into_iter`。`into_` 接頭辞が目印）
- 借用規則は「複数の読者 XOR 単独の書き手」。共有借用（`&`）は何個でも同時に持てるが、
  排他借用（`&mut`）がある間は他の借用が一切共存できない
- 借用の生存期間は「スコープの終わり」ではなく「最後に使った所まで」（NLL）
- move と `&mut` の使い分け基準: 「呼び出した後も自分がその値を使い続けるか」

**参照とデリファレンス**

- 参照の実体はアドレスだが、Rust は表示・比較・メソッド呼び出しで自動的に指し先として
  扱う（アドレスを見るのは `{:p}` で明示したときだけ）
- `*` は参照剥がし。`+=` や `=` など自動剥がしが効かない場面でだけ自分で書く
- `*r += 1`（指し先を増やす）と `r += 1`（アドレス演算＝コンパイルエラー）は別物

**値の寿命 3 パターン**

| 持ち方 | 寿命 |
|---|---|
| 変数に束縛（`let x = ...`） | ブロックの終わり（`}`）まで |
| 名前のない一時値 | その文の終わり（`;`）まで |
| 所有するコピー（`to_string()`） | 新しい持ち主に従う |

- メソッドチェーンを途中で切って `&str` を変数に受けるなら、借用元にも名前を付けて
  生かしておくか、切らずに 1 文で所有（`to_string()`）まで完走する

**文字列**

- `String`（所有）と `&str`（借用）の二本立て。`str` のメソッドは `String` からも呼べる
  （Deref）ので、ドキュメントは両方見る
- `len()` はバイト数（UTF-8）。文字数は `chars().count()`
- `String` → `&str` は `as_str()`（無料の借用）、`&str` → `String` は `to_string()`（コピー）

**コレクションとイテレータ**

- HashMap のカウントアップは `*counts.entry(key).or_insert(0) += 1`
  （`entry` はキー検索 1 回で「有 / 無」両ケースのスロットを掴む API。
  TS の `counts[word] = (counts[word] ?? 0) + 1` の `?? 0` に相当するのが `or_insert(0)`）
- `split_whitespace()` は配列を作らずに 1 単語ずつ生む遅延イテレータ
  （TS の `split()` は配列を即時生成する。この差が題材3のストリーム処理に直結）
- `count()` はイテレータを消費する（`self` を取る）。イテレータは一方通行のカーソル
- `println!("{}")` は Display 実装型のみ。`Vec`/`HashMap` は `{:?}`（整形は `{:#?}`）で見る

### 踏んだエラーと原因（エラーで学ぶのが一番効率が良かった）

1. **`use std::fs` のセミコロン欠け** — `use` 宣言も文。コンパイラの `help:` 行が
   そのまま修正方法になっている
2. **E0382（use of moved value）** — `words.count()` を 2 回呼んだ。読み方の 3 点セット:
   どこで move したか → 誰が奪ったか（シグネチャの self）→ なぜ暗黙コピーされないか
   （`Copy` トレイトの有無）
3. **`lower_word` does not live long enough** — ループ内一時変数への借用（`trim_matches`
   の返り値）を、ループより長生きする HashMap のキーに入れようとした。
   ダングリングポインタをコンパイル時に防がれた形。`to_string()` で所有化して解決
4. **一時値からの借用（チェーン分割時）** — `to_lowercase()` の結果を変数に束縛せず
   借用だけ変数に受けたら、一時値が文末で死んで失敗。1 文に `to_string()` まで
   繋げて解決（上の「寿命 3 パターン」を参照）

### 比較メモの種（TypeScript との対比で気づいたこと）

- 単語カウント程度なら TS の方が素直に短い。行数はほぼ同じだが、Rust だけにあるのは
  `*`/`&mut`（GC が隠しているコストの可視化）と `to_string()`（GC が隠している
  寿命判断の明示）の 2 点
- 「キーが無いときどうするか」問題は言語を問わず存在し、TS は `?? 0`、Rust は
  `Entry` + `or_insert(0)` で解いている。ここの複雑さは実は同等
- Rust のコンパイルエラーは原因位置・理由・修正案（`help:`）の 3 点構成で、
  エラー主導の学習と相性が良い

### 環境まわりの知見

- rust-analyzer はワークスペースルート直下の `Cargo.toml` しか自動探索しない。
  ネストした配置では `.vscode/settings.json` の `rust-analyzer.linkedProjects` で指定する
- `cargo run` の作業ディレクトリは実行した場所。相対パスのファイル参照は
  プロジェクトディレクトリ内から実行する前提にした
- `cargo run -- <args>` の `--` 区切りでプログラム側に引数を渡す
